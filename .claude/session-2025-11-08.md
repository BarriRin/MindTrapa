### Level Selection:
```
MAIN_MENU

    → Block 1 (PushState → LEVEL_SELECT_LEVELS)
```

### Pause Menu:
```
PLAYING
  → ESC (PushState → PAUSED)
    → Settings (PushState)
      → ESC (PopState) → PAUSED
    → ESC (PopState) → PLAYING
    → Main Menu (ClearHistory → MAIN_MENU)
```

## 📝 Code Patterns Established

### 1. Menu State Transitions
```cpp
// Forward navigation - use PushState
menu.PushState(GameState::SETTINGS);
gameState = menu.GetState();

// Backward navigation - use PopState (in Menu.cpp)
PopState();  // Called by ESC or Back button

// Reset navigation - use ClearHistory
menu.ClearHistory();
menu.SetState(GameState::MAIN_MENU);
```

### 2. State Synchronization
```cpp
ButtonAction action = menu.HandleInput(blockToLoad, levelToLoad);

switch (action) {
    case ButtonAction::START_GAME:
        gameState = GameState::PLAYING;  // Manual assignment
        break;

    default:
        if (levelToLoad <= 0) {
            // Only sync if no action occurred (ESC pressed)
            gameState = menu.GetState();
        }
        break;
}
```

### 3. Stack Clearing on Game Start
```cpp
// Always clear stack when entering PLAYING state
menu.ClearHistory();
levelManager.LoadLevel(levelId);
gameState = GameState::PLAYING;
```

## 🎓 Lessons Learned

### Technical:
1. **State management:** Who owns the state? Menu or main.cpp?
   - Solution: Menu owns state, main.cpp follows

2. **Sync timing:** When to sync gameState?
   - Solution: Only when menu changes internally (ESC), not when action processed

3. **Stack lifecycle:** When to clear stack?
   - Solution: On game start, level load, return to main menu
